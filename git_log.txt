    Fix POST complete signal polarity (#19)
    
    BIOS POST complete signal polarity has been reversed in Oak Stream
    architecture. The new signal VW_FM_BIOS_POST_CMPLT_BMC is active-high
    instead of the previous low-assert VW_FM_BIOS_POST_CMPLT_N signal.
    
    This change addresses the OS state dependency issue where the operating
    system status remained inactive after BMC reboot due to incorrect POST
    complete signal detection. The OS state transitions depend on POST
    complete assertion, which in turn depends on CoreBiosDone being true.
    
    Tested
    - AC cycle: OS state correctly transitions to Standby after BIOS boot
    - Chassis reset: OS state properly detected and updated
    - BMC reboot: Host status maintains Standby state when BIOS is running
    instead of remaining in OSStatus.Inactive state
    
    Signed-off-by: Ankita Vilas Gawade <ankita.gawade@intel.com>

    Change sysfs paths for LPC bus access (#15)
    
    Linux kernel DTSIs describing Aspeed AST2600 hardware were recently
    updated. In addition to making the files comply with the schema, the
    hardware description is now matching the reality, with some devices
    being moved to their appropriate place (many devices were incorrectly
    described as being connected over AMBA APB, where they are actually
    connected over AMBA AHB).
    
    Avoid low-level interconnect details when accessing LPC bus using sysfs,
    as using full device tree path may result in failure to detect LPC
    devices on updated kernels.
    
    Tested: LPC buses are correctly found using old and new Aspeed DTSIs.
    
    Link: https://lore.kernel.org/all/20240821-dt-warnings-apb-nodes-v1-1-c524923acca5@codeconstruct.com.au/
